# Errata: things in this repo's history that are wrong and stay there

History is not rewritten, so wrong words in a commit message stay. This file says which ones.

- **1488836** (the accept of `slice/self-managed-and-guard`, 2026-10-13 03:38 UTC, the evening of 2026-10-12 in Denver). The message says "0.1.1" and "reviewed three times by a fresh-context reviewer". Neither was true when written. No version had been bumped (`package.json` said 0.1.0 until the next slice). Only the first of the three reviews was a fresh context; rounds two and three were the same reviewer resumed, so it had seen the earlier version. The three records exist and say what they say, but "fresh" applies to one of them. The author of this note is the author of that message. The three review records and the accept all carry the same session id, 509260993471: the reviewer ran in the author's own clone with no `SL_SESSION` of its own, so the tool could not have told the reviewer and the author apart by session. The same is true of the review of the slice that adds this file.

The save before it said "1070" when the count was 1076, which that message itself corrects, and then got its own number wrong. The author typed both numbers instead of pasting the command's output; the squash message at accept carries the measured number.
